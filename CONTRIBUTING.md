# Contributing

Thanks for helping improve this demo.

## Before opening a pull request

1. Keep each service dependency-free unless a dependency is essential.
2. Add or update tests for changed behavior.
3. Run `make test` and `make compose-config`.
4. If Docker is available, run `make up`, `make smoke`, and `make down`.
5. Do not commit credentials, `.env` files, build output, or personal data.

Use focused pull requests and explain any change to ports, routes, image tags, or security settings in the README.
